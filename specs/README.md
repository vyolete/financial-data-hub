# Especificaciones

Cada funcionalidad tendrá un identificador estable y requisitos verificables. Estructura propuesta: spec.md, research.md (referencias a evidencia), plan.md, tasks.md, checklists y contratos locales cuando se justifiquen. Los contratos compartidos aprobados residirán en contracts/ cuando exista.

Las especificaciones deben identificar alcance, exclusiones, escenarios, requisitos funcionales y no funcionales, criterios de aceptación y estado. Mantenerlas vigentes al cambiar comportamiento. La selección de Spec Kit u OpenSpec está pendiente; adaptar esta organización al framework aprobado sin duplicar fuentes de verdad.
